# Architecture and code smell review, 2026-11-21

Scope: main at 2517e09. Server 1,400 lines Go, client 4,131 lines in one file,
worker 245, tests about 2,000 lines of JS and 1,055 of Go. One Go test file
exists (internal/pq/pq_test.go).

Client baseline: 184 top-level functions, 72 state fields, 688 state reads and
writes, 43 `$('id')` sites, 52 bare `catch {}`, 16 `.catch(() => {})`, 28
`addEventListener`, 1 `removeEventListener`.

## The ten worst smells

1. **Two message handlers, already drifted.** `handle` and `handleSealed` are
   separate switches over the same vocabulary, and `state.sealed` is tested at
   about 40 call sites. The drift is live: `say('')` on `joined` wipes the
   device error (the message is on screen for a few hundred ms), the sealed
   `state` handler has no chat note, and `setPeerState` takes ownership of the
   global `link-text` for every peer. Fix: one dispatcher plus a plain mode and
   a sealed mode adapter. About 350 lines touched, 120 deleted, 2 days.

2. **The status line is the only error channel, and `joined` erases it.** 37
   `say()` calls from deep media and crypto code, one writer, no lifetime, and
   the target is chosen from `state.room`, which `leave()` clears before it
   says why it left. Fix: a notices sink with a source tag and an explicit
   clear. Half a day.

3. **Nothing owns teardown.** `setInterval(pollRelay, 5000)` is created at boot
   and never cleared, so stats polling runs behind a closed panel and in the
   lobby; `wireDots` adds a document listener per remote tile and never removes
   it; sealed frame counters survive a reconnect and mix two connections;
   `state.raw` and `chatNames` are dead fields that look like cleanup. Fix:
   `own()` and `releaseAll()` on peer drop, leave and reconnect. Half a day.

4. **The server lets two goroutines write one websocket.** `writeNow` runs on
   the read goroutine for bad JSON, join refusal and rate limits while
   `writeLoop` may be writing a frame or a ping; `Peer.enqueue` closes a
   connection from another peer's goroutine mid-frame; `mic` and `cam` are
   written and read without a lock, so `-race` would flag them. Fix: one writer
   plus atomic flags. A few hours, and it makes `-race` a usable gate.

5. **68 swallowed errors.** Most are defensible. The ones that cost: the
   quality cap ignores a rejected `setParameters`, `adoptCam` ignores a refused
   `replaceTrack` so the sender keeps the old camera, `stopShare` is async and
   called unawaited, and a failed TURN mint still joins with `path=relay` and
   no candidate. Fix: one fault sink with a bounded ring, used on the dozen
   paths where silence is wrong. One to two days.

6. **The protocol is an implicit contract over six files.** The README table is
   nine message types behind, the client never sends `ping`, the opaque `enc`
   channel carries three different encodings, and the protocol string is
   duplicated in five places, so an AAD change fails at runtime as a confirm
   mismatch and the self test still passes. Fix: `protocol.js` plus a golden
   fixture asserted by the selftest. One day.

7. **No unit-test layer.** The browser suites prove plumbing and pin internals
   (`startLost`, `state.ws`), with fixed sleeps and an exact 29-byte header
   assertion that fails on a correct header change. Nothing tests room name
   parsing, the outbox policy, the bitrate maths, the hub rules. Fix:
   `static/pure.js` with a CommonJS tail and `node --test`, plus `Hub` tests
   with an injected clock. Two days.

8. **The hub is one global lock, two log paths, one E2E flag in five places.**
   Every chat line copies the whole 100-line history under the hub mutex, and
   `-turn-url` hands an external TURN the embedded server's credential. Fix:
   per-room lock, one add-line path, one `blind()` decision. One day, but not
   urgent below 200 rooms.

9. **The asset manifest is a ritual that no-ops.** Every asset is served
   `no-store`, so the `?v=` query changes nothing; the names are listed in
   three places; a new client file needs a manifest entry, a script tag and a
   jsconfig entry. Fix: walk the embed FS for the map, drop the query. Two
   hours, and it is a prerequisite for any file split.

10. **A remote mute rewrites the victim's stored preference.** An admin `mod`
    mute calls `disableMic()`, which stores `mic=0`, so the next visit starts
    muted. Volume is keyed by a peer-controlled name under one flat `rooms.`
    prefix, so two guests called `guest` share a slider. Fix: a prefs object
    with a version and a mute path that does not touch the preference. Half a
    day.

## Order of work

1. One dispatcher plus two mode adapters. It removes the whole "the fix landed
   in one mode" bug class, and both suites already exercise both modes.
2. Notices sink. 3. Owned teardown and the poll interval. 4. One websocket
   writer. 5. `pure.js` and the unit layer.

## Leave alone

- The global `state` and the classic-script globals: four suites drive the page
  by name, so a module conversion deletes the test contract for no user gain.
- The client room id generator next to the server's: it lets the lobby suggest
  an id with no request, and the server keeps no room listing.
- The worklet string bundle: an AudioWorklet cannot import the 1.9 MB synchron
  build, so the alias and the concat are the cheapest correct answer.

## Wasted effort

ES modules, a bundler, a framework or a state library. Splitting the file
before the handler merge. Replacing PBKDF2 with Argon2: the room id is already
128 bits and the passphrase is optional, so it changes no threat.
